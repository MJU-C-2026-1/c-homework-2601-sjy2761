## 🟦 [1차 과제: V1.0] 기초 뼈대 구축 (입출력과 변수)
### **✨V1.0 개발 내용:**
* 사용자로부터 이니셜(문자), 현재/목표 체중(실수), 목표 기간(정수)을 입력받는 화면을 구현했습니다.

* 사칙연산을 활용해 증량 목표와 하루 권장 영양 수치를 계산하여 출력했습니다.

* char, int, float의 3가지 자료형과 8개의 변수를 사용하여 데이터 구조의 완성도를 높였습니다.
    
### **🤖 AI 파트너십 과정**
 1. **내용 1**
    * **프롬프트 요약:** "C언어 4단계 과제 로드맵(입출력 → 조건문 → 반복문 → 배열/함수)에 적합한 헬스 및 벌크업 관리 시뮬레이터 시나리오 기획 요청"
    * **적용 내용:** 단순 무게 계산기를 넘어, '기초 정보 입력(1차)' → '영양 상태 판별(2차)' → '식단/운동 메뉴 시스템(3차)' → '주간 변화 리포트 및 함수화(4차)'로 이어지는 체계적인 확장 로드맵을 확립함.
      
 2. **내용 2**
    * **프롬프트 요약:** "1차 과제 필수 요건(변수 5개 이상 사용)을 충족하기 위한 데이터 구조 고도화 논의"
    * **적용 내용:** 단순히 체중만 다루는 대신, 목표 단백질량, 목표 운동시간, 목표 달성 기간 등 변수를 추가 선언하여 총 8개의 변수를 활용함. 이를 통해 기획의 완성도를 높이고 과제 조건을 완벽히 충족함.
    
### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** 체중 소수점이 너무 길게 출력되어 가독성이 떨어짐.
     * **해결:** printf("%.1f", weight);와 같이 서식 지정자를 수정하여 소수점 첫째 자리까지만 깔끔하게 출력되도록 개선함.
  2. **문제 2:** scanf로 몸무게 입력 시 엉뚱한 값(쓰레기 값)이 저장되는 현상 발생.
     * **해결:** 실수형(float) 변수인 currentWeight에 값을 입력받으면서, 무의식적으로 정수형 서식 지정자인 %d를 사용했던 것이 원인이었음, 자료형과 서식 지정자의 짝을 정확히 맞춰야 한다는 점을 복습하고, %d 대신 %f로 수정하여 데이터를 정상적으로 입력받음.

## 🟩 [2차 과제: V2.0] 조건 분기 적용 (조건문)
### **✨2차 과제 업데이트 내용:**
  * 1차 과제의 기초 계산 기능에 다중 조건문(if ~ else if ~ else), 중첩 조건문, 논리/관계 연산자(&&, ||)를 추가하여 '스마트 벌크업 플래너 V2.0'으로 업그레이드했습니다.
  *사용자가 오늘 실제로 섭취한 칼로리/단백질량과 운동 시간/걸음 수를 입력하면, 프로그램이 1) 영양 섭취 달성도(초과/달성/부족), 2)식단의 질(클린 vs 더티 벌크업), 3) 복합 운동 강도(고/중/저)를 스스로 분석하고 맞춤형 피드백을 제공하도록 로직을 구현했습니다.
    
### **🤖 AI 파트너십 과정**
 1. **내용 1**
    * **프롬프트 요약:** 2차 과제 필수 요건(다중 조건, 중첩 조건, 논리 연산자)을 벌크업 시나리오에 억지스럽지 않고 자연스럽게 녹여낼 수 있는 로직 구성안 제안 요청.
    * **적용 내용:** 로리 달성 여부를 '다중 조건문'으로 크게 분류하고, 목표를 달성했을 때 단백질 섭취량까지 추가로 검사하는 '중첩 조건문'을 적용하여 클린/더티 벌크업을 판별함. 또한, 운동 시간과 걸음 수라는 두 가지 변수를 논리 연산자(&&, ||)로 묶어 복합적인 운동 강도를 평가하는 실용적인 알고리즘을 완성함.
### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** 다중 조건문으로 전체적인 영양 상태를 나누는 것은 구현했으나, 과제 조건인 '중첩 조건문'을 로직의 어느 부분에 넣어야 할지 구조적인 고민이 발생함.
     **해결:** AI와 논의하여 단순히 문법을 끼워 넣는 것이 아니라, "칼로리 목표를 달성한 상태(else if 블록 내부)"에서 "단백질량 까지 충족했는지(if문 추가)"를 한 번 더 묻는 방식으로 해결함. 이를 통해 문법 요건을 채움과 동시에 프로그램의 디테일을 살림.

## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템 (반복문) - 향후 작성 예정
### **✨3차 과제 업데이트 내용:**
  * 메뉴 시스템 및 무한 루프 도입: while(1) 무한 루프와 switch-case 문을 결합하여 사용자가 0을 입력하기 전까지 프로그램이 종료되지 않고 지속해서 메뉴를 선택할 수 있도록 구현함.
  * 기능별 개별 함수 분리 (모듈화): 기존 1, 2차 과제의 코드를 setPhase1Goal, calcDailyCalorie, calcProteinGoal, analyzeDiet, analyzeExercise 등 최소 3개 이상의 독립된 함수로 분리하여 메인 로직을 목차처럼 간결하게 구성함.
  * 매개변수와 반환값 활용: 오늘 섭취량 및 운동량 데이터를 main 함수의 지역 변수로 유지하고, 이를 분석 함수에 매개변수(인자)로 전달하여 처리함. 또한, 칼로리와 단백질 목표 계산 시 return 문을 통해 연산 결과를 반환받도록 구현함.
  * 전역 변수와 지역 변수의 역할 분리: 메뉴 간 데이터 공유가 필요한 목표치 데이터는 전역 변수로 선언하여 함수 내부에서 값을 직접 업데이트하도록 하고, 매회 입력받는 오늘 데이터는 지역 변수로 관리함.
    
### **🤖 AI 파트너십 과정**
 1. **내용 1**
    * **프롬프트 요약:**  `main` 함수에서 입력받은 오늘 하루 데이터(칼로리, 운동 시간 등)를 분석 함수로 안전하게 전달하는 방법과, 특정 연산 결과(권장 칼로리, 단백질 목표치)를 `return`을 통해 메인 로직으로 받아오는 올바른 함수 매개변수/반환값 문법과 설계 구조를 질의함.
    * **적용 내용:** `analyzeDiet(today_calorie, today_protein)` 처럼 함수가 실행될 때 필요한 데이터를 인자로 던져주도록 구현함. 또한, 칼로리와 단백질 계산기를 `int calcDailyCalorie(double weight)` 형태로 독립시켜 연산된 결과를 `return`문으로 반환받아 전역 변수에 대입하는 유기적인 데이터 흐름을 완성함.
    
### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** 모든 변수의 지역 변수화로 인한 데이터 유실 및 조건 미충족
     * **해결:** 초기 설계 시 모든 변수를 main 함수 내부의 지역 변수로만 선언하려고 했으나, 이 경우 1번 메뉴에서 입력·계산된 데이터가 2번 메뉴로 넘어갈 때 유실되는 문제가 발생함. 또한 "전역 변수를 하나 이상 사용하고 값을 업데이트할 것"이라는 요구사항 5번을 위반하게 됨. 이를 해결하기 위해 메뉴 간에 공유되어야 하는 목표 데이터                                 (daily_calorie, protein_goal 등) 는 전역 변수로 빼서 함수 내에서 업데이트되도록 하고, 오늘 하루 입력값만 지역 변수로 선언 후 매개변수로 던져주는 방식으로 타협하여 문제를 완벽히 해결함.
